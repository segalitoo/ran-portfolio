Motion from a static, made in code

Byoma · unsolicited spec work · 2026

The ads in the spec set were signed off as statics. To make them move, the usual step is a video model, and video models warp letters and invent labels. So I asked a different question: if the static is already approved, can the motion be built from it in code, with the type exact, the pack exact, and the last frame the very file I signed?

Spec work. Not commissioned by, affiliated with or approved by Byoma. The labels on the packs were printed by me in the renderer from public product information. None of these ads has run.

Watch the four ads ↓

What I set out to test

Whether motion for an approved static can skip the video model entirely, and still feel designed rather than like a slideshow: real easing, physical landings, timing that follows how people read.

What I decided

Animate the signed file, never a new picture. Every layer comes from the static’s own renderer. Each ad’s motion follows its argument. Every check runs on single frames, not on a viewing.

What I made

A small motion toolkit in Python, built with Claude Code as the engineer and me as the art director, and four 10-second story ads made with it. No generation, no credits, one person signing each one.

Scope

4 story ads1080 × 1920, 60 fps, 10 seconds each, passing the Meta, TikTok and Shorts specs

0 generations, 0 creditsEvery frame composited from the approved static’s own layers

746 lines of codeA shared toolkit and one short script per ad

01 · Why code

The static was already signed. A model would have to earn it again.

In the first round, the loops came from video models. Both free clips for one ad were rejected: one washed the wall into blinds, the other drew the very list of things it was told to avoid. Even the kept clips can only move the photo; the type has to be laid back on top. For ads where the story is in the type and the layout, the photo barely needs to move at all. What needs to move is the argument.

What a model gives

Real physical motion in the photo: hair, breath, a hand. Worth paying for in a lifestyle shot. But every clip is a new picture to check, the label can drift, and the last frame is never the static I approved.

What code gives

The exact type, the exact pack, timing to the frame, and a last frame that is the static. It cannot invent motion inside a photo, so the choice is per ad: chat, data and comparison ads are code; people are the model.

02 · The layers

Every layer comes from the renderer that made the static.

The static renderer draws each ad from a layout file. The toolkit asks it for one item at a time: the logo alone, each headline line alone, each tag, each callout line, the photo with nothing on it. A test composites all the layers back together and compares the result with the signed static: on the B09 ad it matched to within one level of one channel.

Moving the product, too

Where the product moves (the cube on the pump, the tube and its cap), it is cut out of the photo and the wall behind it is rebuilt with the same fill that extends walls for the 9:16 frames. Then it floats on its own layer, and the wall it left is clean even with the contrast pushed.

Built to be checked

Each ad is a script of moves with start times, so a single moment can be rendered without encoding the video. That made it cheap to look at the frame where something changes hands, which is where almost every bug in chapter 05 lived.

03 · The four ads

Each ad moves the way its argument reads.

The same toolkit, four different grammars. The question for each was not “what can move” but “in what order does a person need to read this”. The first frame of each one reads with the sound off, because that frame is the hook.

04 · The curves

Every curve has a job, and the job decides the curve.

Linear motion is what makes code-made animation look cheap. Four curves did all the work across the four ads, each tied to a kind of event. Picking the curve by the event, not by taste, is what kept four ads feeling like one system.

05 · What broke

Playback hides the bugs. Single frames show them.

Each video passed the platform spec checks on its first render. None of them was finished. Seven of these were found by rendering the exact moment where one thing hands over to another, and looking at it. The eighth got past the frame checks and was caught by watching.

  • The dots showed through the replyMom’s typing dots faded out while her message faded in, so for a few frames you could read both. Chat apps swap them on one frame. Fixed to match.
  • One empty frame at the hand-offAfter that fix, the frame where the dots left and the message arrived was blank: 1/60 of a second, a visible flicker. The dots now stay one frame longer.
  • The falling tube crossed the headlineA 300-pixel drop passed behind the type on its way down. The static’s layout checks only ever see the last frame. The drop became a 60-pixel settle.
  • The cut-out lost the shaded sideThe colour test that finds the pack missed the tube’s side where the yellow wall bounces onto it. A new matte measures how yellow each pixel is: the wall is, the pack is not.
  • Pink marks on the rebuilt wallThe tube’s warm-orange underside is as yellow as the wall, so it stayed behind as a smear. A second test, how much redder than green, catches it, but only near the pack, so the floor shadow stays wall.
  • The logo never appearedIn the first B08 render the logo was missing for all 8 seconds: it is an image, and only type was being drawn on the type layer. Now the toolkit fits image items the way the static does.
  • The tube’s edges, caught after reviewThe B02 tube was cut from a mask made at half size and enlarged, so its edges stepped and its shoulder tore. At feed size the static hid it; at full size in motion I saw it at once. Re-cut at full size, with the wall’s colour solved out of every edge pixel.
  • My own frame check liedTo inspect a moment I seeked the video, and the tool jumped to the nearest keyframe a second earlier. Three frames “showed” a bug that was not there. Checks now read the exact frame.

06 · Back in the statics

The same round fixed three things the signed set still had.

Before the motion, two notes of mine went back to the statics: the backgrounds had a strange shadow, and the headlines left too much of the Stories frame empty. Both became checks, so the next set cannot repeat them.

The shadow was a seam

Where a photo was smaller than the frame, the wall was extended with one average colour, so the photo’s rectangle showed as soft bands. The fill now continues each edge’s own colour, and a check measures the bend in the wall’s brightness across every join: 1.8 to 9.0 before, 0.2 to 1.2 after.

Headlines sized by the room

Eye-tracking research says attention to text grows with its size and big type is read first. So the Stories headlines now grow until a line fills the column or the block reaches a fifth of the frame, and a long word may take its own line. Growing them exposed two more gaps: a check now catches type over the product, and sentences stay whole across line breaks.

07 · What I learned

Eight rules for motion made from a static.

Each one came from something on this page going wrong, and each now lives in the toolkit or the lessons file. These are the ones I would give a motion designer working next to an AI agent.

  1. Animate the signed fileLayers from the static’s own renderer, and a test that puts them back together and compares.
  2. Choose the tool per adPeople and fabric: a video model. Type, data and comparisons: code.
  3. Motion follows the argumentAsk in what order a person must read it, then move things in that order.
  4. The first frame is the hookStart mid-move if you must, but never on an empty frame.
  5. Pick the curve by the eventArrive, pop, land, drift: four curves, one job each.
  6. Check the hand-offsRender the frame where one thing replaces another. That is where it breaks.
  7. Layout checks apply mid-motionA static check sees the last frame. A moving part can cross the type on the way.
  8. Read the exact frameA seek that lands on a keyframe will show you a bug that is not there.

08 · What it can’t prove

Better motion, not yet better results.

None of these ads has run, so there is no answer yet to the question that matters: does the moving version beat the static? The pipeline is set up to test exactly that, each motion ad against its own static, once there is a budget and a brand.

  • SilentNo sound design yet. Most Stories are watched muted, but TikTok and Reels reward sound.
  • Short for TikTok10 seconds suits Stories and Shorts. The spec file I check against recommends 21 to 34 seconds for TikTok in-feed ads.
  • Judged by eye and by checksFrame checks and platform specs, not an audience. The timing reads right to me; a test would say if it reads right to buyers.
